Here is exactly how the 81% is calculated. It’s five steps. Step 1: make 72 versions of the class model. I changed the four inputs that matter most. Climate sensitivity takes three values: 1.00, 1.15 (the class value) and 1.30. Response speed takes three: 0.020, 0.0256 (the class value) and 0.032. Emissions after 2024 follow one of four paths: the HW5 economy, falling, flat or rising. Land-use emissions are either left out or added back. Three times three times four times two is 72. Step 2: run each version through the class model. That gives one smooth temperature path for that version from 2027 to 2049. Step 3: simulate 4,000 futures for each version. Each future starts from 2026’s actual temperature, adds random El Niño-style ups and downs each year, and splits into the four datasets Kalshi uses. A future counts as reaching 2°C if, in any year up to 2049, the second-highest of the four datasets is at least 2.00°C. Step 4: count, version by version. The table shows three real examples. The lowest version, with low sensitivity, slow response and falling emissions, reaches 2°C in only 380 of its 4,000 futures, 9.5%. A middle version reaches it in 2,040, about 51%. The class settings with the HW5 economy reach it in 3,975 of 4,000, 99.4%. Step 5: pool all 72 versions. Adding up every version’s count gives 232,668 futures that reach 2°C, out of 72 times 4,000, or 288,000. 232,668 divided by 288,000 is 80.8%. Because every version has the same 4,000 futures, that’s exactly the same as taking the plain average of the 72 percentages. In other words, every version gets equal weight. That 80.8% is also the area past 2.00°C under the green curve on the previous slide, because that curve is built from the same 288,000 futures. Every one of the 72 rows is in the Excel workbook in the GitHub repo, with live formulas, so you can check the arithmetic yourself.
